# 升级到 ZenithProxy 3.8.2（java.26.3.0）——过程与回滚记录

> **结论先说**：2026-11-22 试过一次，**已回滚**。
> 升级本身没问题（插件能编译、面板正常、机器人原生 26.3 上线），
> 但 App 的"连代理"体验没解决 Evernight（1.21.11）客户端的掉线问题。
>
> 这份文档保留全过程，将来要再试时照做即可。

---

## 为什么要升

当时排障发现：

| 项 | 版本 |
| --- | --- |
| 玩家客户端 Evernight | MC **1.21.11**（深度改网络层的 Fabric 客户端） |
| 代理 ZenithProxy | MC **1.21.4** |
| 目标服 3c3u | protocol **777**（ZenithProxy 内部叫 26.3） |

客户端连代理 2 秒后自己断开，日志里刷 4800 行 `handleDisconnection() called twice`。
判断是**版本跨度太大**（1.21.11 → 1.21.4）导致注册表/包结构对不上。

## 升级要点（踩过的坑）

1. **3.8.2 是 Java 25 编译的**（class file 69.0）。服务器原来是 Java 21，
   连它的注解处理器都读不了，`javac` 直接报
   `compiled by a more recent version of the Java Runtime (class file version 69.0)`。
   → 必须装 JDK 25（Temurin）：
   ```bash
   curl -L -o jdk25.tar.gz "https://api.adoptium.net/v3/binary/latest/25/ga/linux/x64/jdk/hotspot/normal/eclipse"
   mkdir -p /opt/jdk25 && tar xzf jdk25.tar.gz -C /opt/jdk25 --strip-components=1
   ```
   （包约 141 MB，服务器直连 adoptium 速度 ~1.8 MB/s）

2. **面板插件要重编**，而且必须跳过注解处理器：
   ```bash
   /opt/jdk25/bin/javac -encoding UTF-8 -source 17 -target 17 -proc:none \
     -classpath ZenithProxy.jar -d build/classes $(find src -name '*.java')
   ```
   `-proc:none` 不加会去加载 ZenithProxy 自带的 `PluginAnnotationProcessor`。
   实测 3.8.2 的插件 API 与 3.7.3 兼容，**10 个类零报错**。

3. **systemd 的 java 要指向 JDK 25**（`/opt/jdk25/bin/java`），否则起不来。

## 升级脚本

`server/upgrade_3.8.2.sh`（自动备份 → 重编插件 → 换 jar → 改 systemd → 起服 → 自检，
自检失败会打印回滚命令）。执行前把新 jar 放到 `/root/ZenithProxy-3.8.2-26.3.0.jar`。

## 升级后的实测结果

```
ZenithProxy 3.8.2+java.26.3.0 - link_cle
Status: Online     Ping: 55ms     Health: 20.0     TPS: 20.03
内存: java RSS 456 MB（比 3.7.3 的 592 MB 更省）
面板: health / 登录 / dashboard / 白名单 3 条 / 喊话配置 / 地图索引 / 日志流 / killAura 命令  全部正常
```

机器人改原生 26.3 连 3c3u（`via zenithToServer off`）也正常上线。

## 为什么又回滚

Evernight 客户端连接仍然会掉（同一现象）。所以升级没能解决"用这个客户端连代理"的问题，
而升级本身带来了新依赖（Java 25），收益不足 → 回滚到 1.21.4 保持现状稳定。

## 回滚步骤

```bash
BK=/root/ZenithProxy/backup/pre-3.8.2-20261122-033916
systemctl stop zenith; sleep 4; pkill -f ZenithProxy.jar; sleep 2
cp -f $BK/ZenithProxy.jar /root/ZenithProxy/ZenithProxy.jar
rm -rf /root/ZenithProxy/plugins && cp -a $BK/plugins /root/ZenithProxy/plugins
cp -f $BK/config.json /root/ZenithProxy/config.json
cp -f $BK/mc_auth_cache.json /root/ZenithProxy/mc_auth_cache.json
cp -f $BK/zenith.service /etc/systemd/system/ && systemctl daemon-reload
systemctl start zenith
```

回滚后校验：`status` 第一行应回到 `ZenithProxy 3.7.3+java.1.21.4`，
`via` 三行恢复成 `on / 1.20.3-1.20.4 / on`。

## 如果将来还想解决 Evernight 掉线

按代价从低到高：

1. **连代理用原版 1.21.4 客户端**（实测稳定），Evernight 只用来直连 3c3u
2. 在 ViaFabricPlus 里给该服务器**强制版本**，减少一层翻译
3. 升级到 3.8.2 + Java 25（本文档的流程），但仍需客户端侧配合
4. 换一个不带协议层 mixin 的客户端连代理
